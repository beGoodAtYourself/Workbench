# Design: 本地个人工作台

**Change ID:** `add-local-personal-workbench`
**Status:** Draft

## 1. 技术方案与依据

建议先验证 Tauri 2 + Rust + TypeScript 静态前端。Tauri 通过核心进程管理系统能力、通过 WebView 渲染界面；Windows 使用 WebView2。这支持将文件与系统操作集中到后端，但仍须计入 WebView 子进程的内存。[Tauri 进程模型](https://v2.tauri.app/concept/process-model/)

使用 CodeMirror 6 的编辑状态、视图、命令与 Markdown 支持模块，按需加载。其模块化设计和视口渲染可用于控制编辑器加载范围与 DOM 数量；实际成本由项目基准验证。[CodeMirror 系统指南](https://codemirror.net/docs/guide/)

全局快捷键可基于 Tauri 官方插件实现；注册失败必须反馈到设置页面，不能只在界面上显示绑定成功。[Tauri Global Shortcut](https://v2.tauri.app/plugin/global-shortcut/)

剪贴板读取可使用官方 Clipboard 插件；Windows 变化通知可通过 `AddClipboardFormatListener` / `WM_CLIPBOARDUPDATE` 接收。本提案仅在剪贴板视图可见时监听，以减少无效读取；插件本身不被假定提供历史收集能力。[Tauri Clipboard](https://v2.tauri.app/plugin/clipboard/)、[Microsoft 剪贴板监听说明](https://learn.microsoft.com/en-us/windows/win32/dataxchg/using-the-clipboard#monitoring-clipboard-contents)

前端先采用 TypeScript 和小型组件层，Markdown 显示采用成熟解析器，关闭原始 HTML 执行，不加入服务端渲染或常驻 Node 服务。解析器、UI 层及依赖具体版本在实施阶段确定并锁定；本提案不把未验证的版本或内存比较当作结论。

| 方案 | 适配点 | 需要验证的成本 | 提案选择 |
|---|---|---|---|
| Tauri + 系统 WebView | Markdown 界面、Rust 文件操作、桌面集成 | WebView 固定开销、悬浮入口与重建延迟 | 首选验证 |
| Windows 原生桌面 UI | 与首版平台一致，可直接集成系统窗口 | Markdown 编辑、渲染及拖拽的开发成本 | 若首选无法达到预算，评估原型 |

不依据安装包体积推断运行内存。若空壳验证已明显超预算，应在主体开发前调整技术决策。

## 2. 窗口与页面

主窗口顶部为「笔记管理」「剪贴板」和必要的设置、隐藏、退出操作。笔记模块布局如下，文件树不计入双分屏数量。

```text
┌─────────────────────────────────────────────────────────┐
│ 笔记管理  |  剪贴板                         设置  隐藏   │
├─────────────┬────────────────────┬──────────────────────┤
│ 文件夹/笔记 │ A.md  编辑/显示     │ B.md  编辑/显示  关闭 │
│ +文件夹     │                    │                      │
│ +笔记       │ 来源笔记           │ 链接目标笔记         │
│ 目录树      │                    │                      │
└─────────────┴────────────────────┴──────────────────────┘
```

- 单窗格时，正文占满文件树右侧区域；新打开笔记默认显示模式。
- 点击文件树笔记，在当前活动窗格打开；第一次打开时使用左窗格。若该文件已在另一窗格打开，则激活已有窗格，避免重复编辑同一文件。
- 双窗格独立维护模式和滚动位置；关闭右窗格后左窗格恢复单栏。
- 「关闭主窗口」解释为隐藏，托盘提供「显示」「退出」。退出前处理保存失败；系统强制结束进程不承诺保存最后尚未提交的输入。
- 默认启用可拖动、置顶但不主动抢焦点的悬浮按钮，用户可关闭；记忆位置并在屏幕变化时限制在可见工作区。
- 快捷键在主窗口隐藏或失焦时显示并聚焦，在已聚焦时隐藏。重复启动激活已有实例。

## 3. 本地数据与文件操作

用户选择一个本地根目录。应用直接读取该目录，不导入到私有数据库，也不复制整库。应用设置存于 Windows 当前用户的应用配置目录，正文保留在用户选择的位置。

| 对象 | 必要字段 | 生命周期 |
|---|---|---|
| WorkspaceSettings | 根目录、快捷键、悬浮开关/位置、窗口位置、上次模块 | 本地小型配置文件 |
| TreeEntry | 相对路径、名称、类型、展开状态 | 按目录加载，丢弃长期折叠的子树缓存 |
| DocumentSession | 规范路径、正文缓冲、磁盘版本、dirty/saving/conflict、编辑历史 | 至多两份打开文档，未保存文档不可淘汰 |
| PaneState | 文档标识、模式、光标、滚动位置 | 左/右两个槽位；恢复信息不含正文副本 |
| ClipboardSnapshot | 当前文本片段、读取状态、是否截断 | 仅剪贴板页面可见期间保留 |

目录枚举只读取元数据；展开目录时才读取其直接子项。正文在打开时加载。文件操作由后端以根目录和相对路径执行，校验真实路径仍位于所选根目录内，不沿符号链接或 Windows junction 递归进入其他目录。

新建文件自动补 `.md` 扩展名，名称不允许包含路径分隔符、Windows 保留名或非法结尾；同名时拒绝覆盖并请用户改名。首版支持重命名与移至系统回收站，不实现文件移动。重命名不自动批量改写 Markdown 链接，操作说明需明确这一点。

保存以文档串行队列处理：比较已知磁盘版本，在同目录写入临时文件并替换目标，完成后才清除对应版本的 dirty。保存期间产生的新输入仍保持 dirty 并触发后续保存；成功响应不得覆盖较新的编辑缓冲。原编码为 UTF-8 的笔记保留 BOM 与换行风格，新建笔记使用 UTF-8。无法可靠解码的文件禁止覆盖，并提示使用外部工具转换。

应用重新获得焦点或手动刷新时，更新已加载目录的元数据并检查打开文档版本。无本地编辑时可重载外部变化；有编辑且磁盘发生变化时暂停自动保存，提示选择载入磁盘版本、另存本地副本或取消。载入磁盘版本前明确提示会丢弃本地修改；不提供无提示覆盖。根目录不可访问时展示错误并保留文档缓冲，不自动创建空目录冒充原笔记库。

## 4. 编辑与链接

每个窗格只有「编辑」或「显示」一种模式。编辑是 Markdown 源码编辑；显示支持标题、段落、列表、引用、代码块、表格、任务列表和标准链接。模式切换使用当前缓冲渲染，不额外占用一个文档窗格。初版不加入公式、图谱或复杂图表扩展。

从文件树拖入一个 `.md` 文件时，在编辑区落点插入 `[名称](相对路径)`；名称默认不含 `.md`。显示模式不接收正文修改，拖拽文件夹不插入链接。相对路径相对于来源笔记的父目录，使用 `/` 分隔，按路径段进行 URL 编码；标签中的 Markdown 特殊字符需转义。

示例：来源 `项目/计划.md`，目标 `资料/API 说明.md`，插入 `[API 说明](../%E8%B5%84%E6%96%99/API%20%E8%AF%B4%E6%98%8E.md)`。链接编码和解析应往返一致，不能把文件名中的 `#` 当成片段或将 `%` 重复解码。

显示模式单击链接打开；编辑模式 `Ctrl+单击` 打开，普通单击定位光标。有效链接包括生成的链接及手写的普通本地 Markdown 相对链接。相同文件或 `#标题` 片段只在来源窗格定位，不生成重复文档。跨文件带片段的链接先按双分屏打开，再定位标题；标题不存在时打开文件并给出轻提示。

`http/https` 链接由用户点击后交给系统浏览器，不产生笔记分屏。远程图片初版显示占位，不自动联网获取；工作区内的本地图片延迟加载。其他协议、根目录外文件和非 Markdown 文件给出不支持提示，不交给任意系统程序执行。

## 5. 双分屏状态转移

「来源」始终指用户刚刚点击链接所在的笔记。窗格更新在目标成功读取、被移出文档完成保存处理后一次性提交；目标失败或用户取消时维持原布局。

| 当前状态 | 操作 | 成功后的状态 |
|---|---|---|
| 单栏 A | A 中打开 B | 左 A，右 B，右侧获得焦点 |
| 左 A，右 B | 左侧 A 中打开 C | 左 A，右 C |
| 左 A，右 B | 右侧 B 中打开 C | 左 B，右 C；A 被移出 |
| 左 A，右 B | 右侧 B 中打开 A | 左 B，右 A，复用原会话 |
| 任意布局 | 来源打开自身或自身片段 | 来源窗格定位，布局不变 |
| 左 A，右 B | 关闭右窗格 | A 单栏 |

来源会话连同编辑模式、光标、滚动和未保存缓冲一同保留；目标已打开则复用现有会话，否则默认显示模式。涉及移出 dirty 文档时先立即保存；失败则保留布局并允许重试、另存副本或取消。首版不增加「关闭后仍留在内存的隐藏标签页」。快速连续打开时使用请求序号，过期读取结果不能覆盖较新的跳转。

## 6. 剪贴板首版边界

当前按「只显示当前文本」起草，尚无用户对历史范围的明确确认。进入剪贴板模块或重新显示该模块时立即读取，之后仅在视图可见时监听系统变化，并提供手动刷新。其他模块不依赖剪贴板读取成功。

空剪贴板、非文本内容和临时读取失败分别展示明确状态，不能继续把过期文本标为当前内容。单次显示上限为 1 MiB UTF-8 文本，按完整字符截断并标注；实现应在读取边界限制分配，避免先复制巨量内容再截断。离开视图后取消订阅并清理快照，不存数据库、磁盘文件或日志。

## 7. 内存与唤起预算

以下数值为本次提案提出的验收预算，不是已测量结果。阶段 1 先建立发布构建基线；如预算不合理，应附数据调整提案，不能把开发构建结果或宿主单进程数据当作验收通过。

统一环境：Windows 11 x64、至少 8 GB RAM、SSD，记录 CPU、系统版本、WebView2 版本、屏幕缩放及构建版本。用户只确认 Windows；此配置是基准环境，兼容 Windows 10 与 ARM64 的范围在实施前记录，不默认宣称支持。

基准库包含 1,000 篇笔记、50 个目录，正文平均 20 KiB；单/双笔记使用每篇 100 KiB 的纯 Markdown 样本。另测 2 MiB 笔记和含本地图片的笔记，单独报告其成本。

| 场景 | 测量方式 | 拟议目标 |
|---|---|---|
| 隐藏常驻，悬浮入口开启 | 主窗口隐藏 60 秒后采样 30 秒 | 私有工作集总和 P95 ≤ 120 MiB |
| 单笔记，文件树可见 | 稳定 10 秒后采样 30 秒，显示与编辑分别测量 | P95 ≤ 200 MiB |
| 双笔记，文件树可见 | 两篇均编辑与均显示分别采样，取较高结果 | P95 ≤ 260 MiB |
| 已运行应用唤起 | 按键/点击至正文可交互，测量 30 次 | 保留界面 P95 ≤ 300 ms；闲置卸载后 P95 ≤ 1,000 ms |
| 重复操作后的保留内存 | 预热后执行 100 次循环，恢复同一状态并等待 60 秒 | 私有工作集和 Private Bytes 增量各 ≤ 20 MiB |

内存指标汇总本应用宿主、WebView2 浏览器/渲染/GPU/工具子进程和悬浮入口所属进程，每个 PID 仅计一次，使用独立的应用 WebView 用户数据目录辅助归属；不将无关 Edge 实例计入，也不能漏计渲染进程。每秒采样一次，另报 Private Bytes、峰值和子进程清单。重复测试至少三轮，保留原始记录。

重复循环覆盖：显示/隐藏、切换模块、打开/关闭双分屏、切换显示/编辑、保存、替换目标。最后每轮均返回相同文档与窗口状态，以便比较资源是否持续累积。

资源策略：

- 最多两个文档会话和两个编辑器；模式切换释放不用的重型视图，文档缓冲不无谓复制。
- 不遍历读取整库正文，不维护无限历史、全文索引或无限预览缓存；文件树大列表按可见范围渲染。
- 已关闭文档释放正文、语法树、事件和图片资源；只保留最多两个文档的恢复元数据。
- 隐藏时暂停渲染与剪贴板监听；超过 60 秒且保存成功后卸载主界面，保留系统入口。存在 dirty 或冲突文档时延后卸载，以内容保留优先，并单独报告该状态内存。
- 超过 2 MiB 的笔记先提示并由用户选择继续加载或取消，不静默截断或覆盖正文；大图延迟解码并限制同时保留的图像资源。

## 8. 实施顺序

先完成窗口、悬浮入口和编辑器的最小内存验证，再实现本地文件与保存协议，然后实现 Markdown 交互和分屏事务，最后接入完整系统交互并运行验收。具体任务与质量门槛见 [tasks.md](tasks.md)。

## 9. 归档时的实现与验证状态

2026-09-11 按用户要求提前归档。已采用 Tauri 2 / Rust / TypeScript、单主 WebView 与原生 Win32 悬浮入口，隐藏 60 秒后卸载主界面。第 7 节预算保留为验收目标，完整三轮内存、唤起延迟与循环测试尚未完成。

实现中收紧资源上限：最多展开 300 个目录；撤销记录累计 200 次正文变更或 4 Mi 个插入字符后重置历史，保留当前正文；笔记超过 2 MiB 提示、超过 64 MiB 拒绝；本地图片限制 4 MiB / 800 万像素，每窗格最多两张；剪贴板保留最多 1 MiB UTF-8，按不拆分代理对的最多 4,096 个 UTF-16 代码单元分段浏览，离开模块或隐藏后释放快照。

实际实现与验收的映射见 [待验收清单](../../../docs/verification/deferred-tests.md)，已有结果见 [验收记录](../../../docs/verification/README.md)。本节记录归档状态，不将部分测量视为全面验证。
