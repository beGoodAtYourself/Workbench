# Delta: 拖拽链接与双分屏

**Change ID:** `add-local-personal-workbench`
**Affects:** 文件树拖拽、Markdown 链接解析、文档会话、分屏状态

## ADDED

### Requirement: LINK-01 拖拽生成可移植链接

用户将文件树中的单个 `.md` 文件拖入编辑模式窗格时，应用必须（MUST）在落点插入标准 `[名称](相对路径)` 链接。路径相对于当前笔记父目录，使用 `/` 分隔并正确编码特殊字符；不得移动或复制目标文件。

#### Scenario: 跨目录及特殊字符路径
- GIVEN 来源为 `项目/计划.md`，目标为 `资料/API 说明.md`，来源处于编辑模式。
- WHEN 用户将目标拖到正文指定位置。
- THEN 插入 `[API 说明](../%E8%B5%84%E6%96%99/API%20%E8%AF%B4%E6%98%8E.md)`，保存重开后仍指向同一文件；中文、空格、`#`、`%`、括号和方括号的变体均正确转义或编码。

#### Scenario: 不支持的拖拽
- GIVEN 用户拖拽文件夹或将笔记拖入显示模式。
- WHEN 用户释放鼠标。
- THEN 不修改正文，不误触文件移动，界面显示该落点或项目不支持插入。

### Requirement: LINK-02 明确的打开手势与目标边界

应用必须（MUST）支持显示模式单击、编辑模式 `Ctrl+单击` 打开根目录内的相对 Markdown 链接，包括手写链接。编辑模式普通单击仅定位光标。库外路径和非 Markdown 文件不得作为笔记打开。

#### Scenario: 生成链接与手写链接均可用
- GIVEN 文中包含指向有效本地 `.md` 的生成链接和手写相对链接。
- WHEN 用户使用对应模式的打开手势。
- THEN 解析到正确文件，并按双分屏规则打开；普通编辑单击不会触发导航。

#### Scenario: 缺失目标或非笔记链接
- GIVEN 目标缺失、无权限、位于根目录外，或为不支持的协议/文件格式。
- WHEN 用户尝试打开链接。
- THEN 显示明确原因，保留原文件和布局；合法 `http/https` 链接则交给系统浏览器，不创建笔记窗格。

### Requirement: LINK-03 最大双分屏与来源规则

任意时刻必须（MUST）最多显示两个笔记窗格，左侧文件树不计入。跨笔记链接成功打开后，左窗格必须显示发起此次点击的来源笔记，右窗格必须显示目标笔记；右侧获得焦点。

#### Scenario: 首次跳转与左侧继续跳转
- GIVEN 当前只有 A，或已经显示左 A、右 B。
- WHEN 从 A 打开 B，或从左侧 A 打开 C。
- THEN 分别显示 A｜B 或 A｜C，来源 A 的模式、光标、滚动和缓冲保留，不生成第三个窗格。

#### Scenario: 右侧继续跳转
- GIVEN 左侧 A、右侧 B，B 中包含指向 C 的链接。
- WHEN 用户从 B 打开 C，且 A 已完成保存处理。
- THEN 布局变成左 B、右 C；B 保留原会话状态，A 会话移出并释放，不保留隐藏的第三个编辑器。

### Requirement: LINK-04 已打开目标、自身链接与关闭

目标已打开时必须（MUST）复用会话，不能产生同一文件的两份独立可写缓冲。自身文件或自身片段仅在来源窗格定位。关闭右侧后必须恢复左侧单栏，并处理右侧未保存修改。

#### Scenario: 右侧链接返回左侧文件
- GIVEN 左 A、右 B，B 链接指向 A。
- WHEN 用户从 B 打开 A。
- THEN 变为左 B、右 A，两个原会话被复用，编辑内容不回退。

#### Scenario: 自身链接和带片段链接
- GIVEN 来源链接指向自身文件、自身标题片段或其他笔记标题。
- WHEN 用户打开链接。
- THEN 自身目标不改变布局；其他笔记按左来源、右目标打开并定位标题；缺失标题时保留已打开文件并提示。

#### Scenario: 关闭右窗格
- GIVEN 左 A、右 B，B 有未保存编辑。
- WHEN 用户关闭右窗格。
- THEN 保存成功后释放 B 并以单栏显示 A；失败时保留 B，取消不改变布局。

### Requirement: LINK-05 跳转事务与过期结果

应用必须（MUST）先验证并读取目标，再处理被移出文档的保存，最后一次性提交会话布局。读取失败、保存失败或用户取消时不得破坏原布局。异步过期结果不得覆盖较新请求。

#### Scenario: 保存失败阻止替换
- GIVEN 左 A、右 B，A 有未保存内容，用户从 B 打开 C。
- WHEN C 可读取但 A 保存失败。
- THEN 保留 A｜B 和两份编辑缓冲，提示重试、另存副本或取消；不提前释放 A。

#### Scenario: 快速连续点击
- GIVEN 用户从同一来源连续请求打开 B 和 C，B 的读取比 C 慢。
- WHEN C 已成功打开，随后 B 的读取返回。
- THEN 仍显示来源｜C，丢弃 B 的过期结果并释放临时资源。
