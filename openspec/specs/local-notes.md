# Specification: 本地笔记文件管理

**来源：** [add-local-personal-workbench](../archive/2026-09-11-add-local-personal-workbench/proposal.md)

**状态：** 2026-09-11 合并为正式规格；按用户要求提前归档，剩余验证见 [待验收清单](../../docs/verification/deferred-tests.md)。以下要求是后续验收依据，不表示全部场景已经通过。

## Requirements

### Requirement: FILE-01 本地文件作为正文来源

应用必须（MUST）允许用户选择一个本地根目录，直接管理其中的 UTF-8 `.md` 文件与真实文件夹，记住所选目录，并在断网时完成核心笔记操作。正文不得依赖数据库或远程服务才能读取。

#### Scenario: 选择已有笔记目录并重新打开
- GIVEN 本地目录已包含嵌套文件夹与中文命名的 `.md` 文件。
- WHEN 用户选择该目录，打开并保存笔记，然后退出重开应用。
- THEN 文件保持在原目录，树结构与磁盘一致，应用显示已保存的正文，外部文本编辑器也能直接读取。

#### Scenario: 根目录不可访问或切换目录
- GIVEN 当前根目录无法访问，或用户选择新的根目录。
- WHEN 应用刷新当前目录或准备切换。
- THEN 不把访问失败显示为空库；保留打开文档缓冲，切换前完成未保存文档处理，取消时仍保留原工作区。

### Requirement: FILE-02 文件树与新建

笔记管理必须（MUST）左侧显示文件夹与笔记树、右侧显示正文；支持展开/折叠、新建文件夹、新建 `.md` 文件及手动刷新。点击笔记在活动窗格打开，若已打开则激活对应窗格。

#### Scenario: 在选定目录新建
- GIVEN 用户选中一个文件夹。
- WHEN 用户新建文件夹或输入不含扩展名的笔记名称。
- THEN 在该文件夹下创建真实目录或补 `.md` 的文件，成功后更新树；新笔记在活动窗格以编辑模式打开。

#### Scenario: 名称不合法或已存在
- GIVEN 同目录已有同名项目，或输入 Windows 非法文件名。
- WHEN 用户提交新建或重命名。
- THEN 不覆盖已有项目、不更新为虚假成功状态，并提示可修正的原因。

### Requirement: FILE-03 重命名与回收站

应用必须（MUST）支持文件及文件夹重命名、移至系统回收站。删除前必须确认目标与文件夹影响范围；回收站失败时不得自动改为永久删除。重命名必须更新已打开文档的路径映射，但首版不自动改写正文中的引用。

#### Scenario: 重命名已打开文件或其父目录
- GIVEN 文件处于打开状态，可能存在其他笔记引用它。
- WHEN 用户完成保存处理并重命名文件或父目录。
- THEN 树与打开会话路径同步，界面说明已有相对引用可能需要手动修复；后续保存使用新路径。

#### Scenario: 删除包含打开笔记的目录
- GIVEN 一个目录包含打开笔记，且其中有未保存修改。
- WHEN 用户确认移至回收站。
- THEN 先完成修改保存或取消处理；回收站成功后关闭受影响会话并更新树；失败时保留文件、会话和失败提示。

### Requirement: FILE-04 可靠保存与版本冲突

应用必须（MUST）在停止输入 500 ms 后尝试自动保存，`Ctrl+S` 立即保存。必须串行处理同一文档写入、保存前校验已知磁盘版本、以临时文件替换方式降低部分写入风险。失败不得清除 dirty 或丢弃缓冲。

#### Scenario: 保存期间继续输入
- GIVEN 第一版内容正在写入磁盘。
- WHEN 用户输入第二版内容，随后第一版写入成功。
- THEN 仅第一版被确认保存，第二版仍保持 dirty 并排队保存，界面不回退到第一版。

#### Scenario: 外部修改与写失败
- GIVEN 磁盘内容在读取后被外部程序改写，或本次写入因权限/磁盘问题失败。
- WHEN 应用尝试保存本地修改。
- THEN 不将失败标记为成功；冲突时暂停自动保存，允许载入磁盘版本、另存本地副本或取消，丢弃本地修改必须明确确认。

### Requirement: FILE-05 编码与外部变化

应用必须（MUST）支持 UTF-8 中文正文，保留已有 UTF-8 BOM 与换行风格；不能可靠解码时不得覆盖文件。重新获得焦点或手动刷新时必须检查已加载目录及打开文档的磁盘变化。

#### Scenario: 外部修改无 dirty 文档
- GIVEN 打开笔记没有本地未保存编辑。
- WHEN 外部程序修改文件，用户返回应用或刷新。
- THEN 应用更新正文与树；若文件被移除则提示缺失，不通过自动保存重新创建它。

#### Scenario: 文件编码不支持
- GIVEN 一个 `.md` 文件不能作为 UTF-8 正确解码。
- WHEN 用户打开该文件。
- THEN 提示编码不支持，不以替换字符内容覆盖原文件。

### Requirement: FILE-06 文件操作根目录边界

应用必须（MUST）在后端校验规范路径与根目录的关系，禁止通过路径穿越、符号链接或 Windows junction 访问根目录外文件；文件树不得沿链接形成无限递归。

#### Scenario: 链接目录指向库外或形成环
- GIVEN 笔记目录包含指向外部目录或祖先目录的 junction/符号链接。
- WHEN 用户展开、打开或提交相关文件操作。
- THEN 应用不给予库外访问，不递归成环，并明确提示该项不支持。
