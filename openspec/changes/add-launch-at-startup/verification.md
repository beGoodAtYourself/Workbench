# 开机自启动实施与验证

**Change ID:** `add-launch-at-startup`
**日期：** 2026-10-14
**状态：** 代码和产物已完成，自动化及隔离原生验证通过；真实登录及部分人工验收待完成，尚未归档。

## 已实现

- 设置新增「开机自启动」，默认关闭，读取实际系统注册状态，支持开启、关闭、取消、重试及另一副本位置提示。
- 当前用户的固定 Run 值使用带引号的程序绝对路径及 `--autostart`；不持久化自启动布尔缓存，不在普通启动或保存其他设置时补回注册，不修改 StartupApproved。
- 登录来源的后台启动不创建主 WebView、不读取正文、不监听剪贴板；手动唤起按需创建界面并恢复会话，自动重复启动保持当前状态，明确退出保留注册。
- 快捷键、自启动、本地设置串行变更，注册表使用原类型及原字节快照恢复；外部变化、恢复失败及实际状态在界面中反馈。
- 正常卸载仅清理指向自身的项；替换卸载通过 `/UPDATE` 保留开关，路径迁移检查快照，保护另一副本和外部删除／修改。

首次原生检查发现：在同步单实例 Win32 回调中首次创建 WebView 会阻塞第二个进程。所有显示入口已改为 worker 向主事件循环排队，之后第二进程退出、首次恢复与后续显示／隐藏验收通过。旧设置中无法注册的快捷键也可在设置中修复，成功后清除该启动错误，保留配置解析警告。

## Windows 原生启动检查

使用发布构建、独立身份 `local.shiye.workbench.startupqa`、独立进程名 `shiye-startup-qa.exe`、合成笔记及固定 QA Run 值。环境为 Windows x64／OS version `10.0.26200`，Node `24.18.0`、Rust/Cargo `1.98.0`，本机 WebView2 Runtime。正常 Windows 权限下通过本地 WebView2 CDP 自动化，不使用个人笔记。

`node scripts/startup-native-smoke.mjs` 的 [14 项原始记录](../../../docs/verification/raw/startup-native.json)全部通过：

- 带 `--autostart` 首启没有主界面或 WebView2 子进程，且不自行注册；重复自动启动第二进程退出。
- 手动重复启动唤起原宿主，恢复合成笔记；可见状态的重复自动启动保持窗口状态。
- 中文／空格目录程序可注册，命令精确为带引号路径及来源参数；取消不改变注册。
- 旧 revision 拒绝外部修改，关闭不删除另一副本，显式开启可切回当前副本。
- 用测试目录中的同名目录阻止 settings.json 原子替换，实际保存失败后恢复 Run 原值及旧设置；恢复测试只作用于合成数据。
- 外部删除后界面显示关闭，保存未变选项不补回注册。
- 真实隐藏 60 秒后销毁主 WebView，测得约 **60.08 秒**；自动重复启动仍保持无主界面，手动启动可恢复正文。
- 明确退出保留自启动项，之后带参数启动仍按需加载；关闭开关移除 QA 项。
- 后台快捷键注册失败留待首次唤起提示，可改为合法快捷键后正常保存。

[设置界面截图](../../../docs/verification/startup-native-settings.png)已检查。系统库的单实例及 Tao 消息目标窗口不能仅凭 WS_VISIBLE 判断为界面；检查同时记录窗口类、尺寸、标题和 WebView2 子进程。WebView2 退出时偶有窗口类注销错误 1412，测试仍正常完成，原始 stderr 保留在记录中。

普通沙箱环境无法完成首次 WebView2 初始化；上述最终验收在获自动审批的正常 Windows 环境执行。正式拾页进程 PID `37572` 持续运行，正式 Run 值及类型保持原状，QA 项及进程结束后已清理。

## NSIS 原生生命周期

`node scripts/startup-installer-native.mjs` 的 [8 组原始记录](../../../docs/verification/raw/startup-installer-native.json)通过，**12 次实际安装／卸载退出码均为 0**：

- 首次安装不注册，关闭状态的静默覆盖安装和 `/UPDATE` 卸载／重装保持关闭。
- 开启状态的静默覆盖及 `/UPDATE` 卸载／重装保留注册。
- 中文／空格目录 A 迁移到 B 更新目标路径；之后卸载 A 保留指向 B 的项。
- 注册指向另一独立副本时卸载 B 不误删；正常卸载自身清理自身项。
- 固定 QA 身份、进程名、安装元数据和工作区目录均在执行前核验；正式进程、Run 值和类型前后不变。

安装全程使用 `/S`、不使用 `/R`，没有启动验收程序。安装文件、卸载器、QA Run 及独占安装元数据已清理。静默安装不经过版本选择 GUI，所以 GUI 跨版本升级不视作已通过。

安装后的程序与独立程序仅有官方 bundle marker 的 **3 字节**差异：`__TAURI_BUNDLE_TYPE_VAR_UNK` → `__TAURI_BUNDLE_TYPE_VAR_NSS`。脚本检查完整文件与仅修改这一标记的预期字节完全一致，同时保存原始哈希、归一化哈希及差异偏移；不忽略其他字节。模板基于锁定的 CLI `2.11.4`／bundler `2.9.4`，上游原文、四处补丁和完整 MIT 许可证位于 `src-tauri/windows/`。
