# Proposal: 开机自启动

**Change ID:** `add-launch-at-startup`
**Created:** 2026-10-14
**Status:** Implemented — Acceptance Pending
**Implemented:** 2026-10-14

## 问题与目标

拾页已有托盘、悬浮入口和全局快捷键，但用户登录 Windows 后仍须手动运行程序。现有设置只提供快捷键和悬浮入口开关，首次启动与重复启动均会显示主窗口。

本变更增加可选的「开机自启动」，让用户登录后即可通过现有入口调出工作台，同时避免登录时弹出笔记窗口或加载编辑器资源。

## 拟议行为

- 在「工作台设置」中增加「开机自启动」复选框，说明「登录 Windows 后在后台运行，可通过托盘、悬浮入口或快捷键调出」。没有已有注册项的新装及旧版升级默认关闭；用户开启并保存后才注册。
- 仅作用于当前 Windows 用户。这里的「开机」指用户登录桌面后启动，不在登录前运行。Windows 可以延迟启动，不承诺登录后固定秒数内就绪。[Windows Run 注册机制](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)
- 自动启动带 `--autostart` 参数，只初始化配置、托盘、快捷键及按偏好显示的悬浮入口，不创建主 WebView，不抢占焦点。用户唤起后按现有流程创建界面并恢复会话。
- 手动运行仍显示主窗口。重复手动运行唤起已有实例；重复自动运行保持已有窗口的显示、焦点及会话状态，不创建第二个实例。
- 关闭并保存后移除当前副本的自启动项；取消设置不改变注册。明确退出结束本次运行，保留注册，下次登录仍可启动，不在当前会话自动重启。
- 每次打开设置查询实际注册项；外部删除后显示关闭，不根据缓存自动补回。开关表示当前副本的注册状态，系统仍可能禁止执行；界面提示可在 Windows「应用 → 启动」检查，不覆盖系统禁用决定。[Windows 启动应用管理](https://support.microsoft.com/en-us/windows/experience/startup-boot/configure-startup-applications-in-windows)
- 系统项指向另一拾页副本时，显示目标位置和未为当前副本开启的状态。用户主动开启并保存可切换到当前程序；关闭或卸载当前副本不删除另一位置的项。保存其他设置不重写注册。
- 保存失败不提示成功，尝试恢复原注册值、快捷键及本地设置；恢复也失败时明确说明部分变更并重新读取实际状态，保留重试入口。

## 范围

### 包含

- Windows 11 x64 发布版的当前用户登录启动，覆盖现有 NSIS 安装版和独立 `shiye.exe`。
- 注册查询、开启、关闭、路径引用、错误恢复和设置界面接入。
- 自动启动来源识别、单实例兼容及主界面按需创建。
- NSIS 正常卸载清理与升级状态保留，原生验收及使用说明。

### 不包含

- macOS、Linux、Windows 10 或 ARM64 的兼容性承诺。
- 全用户启动、管理员提权、Windows 服务、计划任务、登录前运行。
- 自动重启、守护进程、自定义启动延迟、安装时默认开启。
- 修改系统启动许可、自动寻找已移动程序、多个副本的优先级管理。
- 首版历史性能延期项目的完整补验。

## 技术方案与现有模式

1. 新增 Rust 自启动模块，复用 `windows-sys` 并增加 `Win32_System_Registry` 功能。通过注册表 API 操作 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 中固定值名 `local.shiye.workbench`，值类型为 `REG_SZ`，命令为 `"<当前程序绝对路径>" --autostart`。正确引用中文／空格路径，构造后超出 Run 的 260 字符限制则失败并保留原值；不使用 shell 拼接执行命令。
2. 系统注册值是事实来源，不增加会在启动时强制回写的持久布尔值。查询区分未注册、当前副本、另一副本及读取失败，返回目标位置。保留操作前原始值和类型用于回滚；读取失败时禁用该开关并允许重试，其他可用设置仍可单独保存。
3. 设置保存沿用 [现有命令](../../../src-tauri/src/commands.rs) 的快捷键预注册及失败撤销模式。开关有改动时才写注册表，相关操作串行执行，完成本地原子保存与注册读回后才成功。关闭仅删除目标匹配当前程序的值；检测到外部变更时刷新状态并提示重试。
4. [启动入口](../../../src-tauri/src/app.rs) 的 setup 与单实例回调共同识别 `--autostart`。配置已有 `app.windows = []`，后台启动直接跳过 `show()`；首次唤起先经 worker 向主事件循环排队，避免在 Win32 消息回调中首次创建 WebView 时阻塞。可恢复的配置解析错误及快捷键注册失败保留到首次打开界面提示，不自动抢焦点。沿用 SHELL-03、SHELL-04 和 PERF-01、PERF-02。
5. NSIS 使用安装器 hooks，仅在正常卸载且注册目标匹配被卸载的程序时删除该值。由于默认模板在 PREINSTALL hook 前就可能运行旧卸载器，实施采用锁定 CLI 2.11.4／bundler 2.9.4 的官方模板及四处小范围补丁，在 .onInit 读取快照、替换安装传递 /UPDATE、由专属 hook 处理 Run 值；上游原文与 MIT 许可证一并保留。升级保留开启／关闭状态，必要时更新路径；GUI 分支与真实登录的完整验收仍见下方状态。[Tauri NSIS 扩展接口](https://v2.tauri.app/distribute/windows-installer/#extending-the-installer)
6. 开发构建和 `SHIYE_DATA_DIR` 隔离运行禁止写正式自启动值；原生验收同时使用独立应用 identifier 和独立注册值名。独立程序移动后旧路径不自动修复，说明中指引在新位置主动开启并保存，替换旧路径注册。

当前工作区已有文件夹／笔记整理的未归档变更。本提案使用独立目录，不依赖其新增要求；实施时保留其他变更及其验收状态。

## 影响分析

| 组件 | 变更 | 说明 |
|---|---|---|
| 系统注册 | 是 | 当前用户的单个 Run 值；无数据库或服务 |
| Rust 后端 | 是 | 注册模块、查询与保存、启动来源和单实例回调 |
| 本地状态 | 是 | 运行时注册查询结果及错误；既有 settings.json 兼容 |
| 前端 | 是 | 开关、目标位置、错误及重试；桥接类型和演示模式 |
| 安装包 | 是 | NSIS hooks、正常卸载清理和升级状态保留 |
| 正式规格 | 待归档 | 新增 SHELL-05、SHELL-06，修改 SHELL-01、SHELL-04 |

## 成功标准

- [ ] 新装及未开启的旧版升级不添加自启动项；开启／关闭／取消符合操作结果。
- [ ] 普通用户可操作，无 UAC 提示；中文或含空格路径可正确启动，超长命令显式失败。
- [ ] 实际注销再登录后保持一个后台实例，主 WebView 尚未创建，入口可用且首次唤起恢复会话。
- [ ] 重复自动启动不抢焦点，手动启动正常唤起；明确退出不立即重启。
- [ ] 注册与设置保存失败可定位、恢复或重试，不呈现虚假的成功状态。
- [ ] 正常卸载清理自身项，覆盖升级保留开关，另一副本的注册不会被误删。
- [ ] 隔离验证可复现，既有隐藏／唤起与保存协议保持可用。

## 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 系统策略、权限或任务管理器禁用使登录时不运行 | 中 | 中 | 说明注册与执行许可的差异，不自动绕过禁用 |
| 快捷键、本地文件和注册表无法组成单一原子事务 | 中 | 中 | 串行保存、保留原值、回滚及读回，部分失败明确反馈 |
| 升级卸载流程误删启用状态 | 中 | 高 | 核对锁定版本 NSIS 模板并验收完整升级流程 |
| 独立程序路径变化或另一副本占用注册 | 中 | 中 | 展示目标位置，显式开启切换，关闭／卸载校验所属路径 |
| 开发与验收污染真实用户注册 | 低 | 高 | 禁止写正式值，使用独立身份和值名，验收结束清理 |
