# Delta: 已在文本模块打开的笔记链接

**Change ID:** `add-text-editor-module`
**Affects:** LINK-02、LINK-03、LINK-05；沿用 LINK-01、LINK-04 和 FILE-11

## ADDED

（无。）

## MODIFIED

### Requirement: LINK-02 明确的打开手势与目标边界

应用必须（MUST）支持显示模式单击、编辑模式 `Ctrl+单击` 打开根目录内的相对 Markdown 链接，包括手写链接。编辑模式普通单击仅定位光标。库外路径和非 Markdown 文件不得作为笔记打开；文本模块的文件授权不扩大笔记链接边界。

目标为当前根目录内合法 `.md` 且已在文本模块打开时，按 FILE-11 激活其已有文本会话，保留笔记布局，不创建第二份缓冲。该例外不得把笔记链接变成无需原生选择的库外文本打开入口。

#### Scenario: 普通目标与文本所有者

- GIVEN 笔记包含分别指向未打开 B.md 和已在文本模块打开 C.md 的有效库内链接。
- WHEN 使用对应模式打开手势。
- THEN B 按笔记双分屏打开；C 切换至已有文本标签，保留其 dirty 和原笔记布局。普通编辑单击不导航。

#### Scenario: 缺失、库外或非笔记目标

- GIVEN 链接目标缺失、无权限、位于库外或为不支持的协议／格式，即使文本模块曾授权该文件。
- WHEN 尝试打开链接。
- THEN 保留来源和布局并说明原因；合法 HTTP／HTTPS 仍交给系统浏览器，不创建笔记窗格。

### Requirement: LINK-03 最大双分屏与来源规则

任意时刻必须（MUST）最多显示两个笔记窗格，左侧文件树不计入。通常跨笔记链接成功打开后，左窗格显示发起此次点击的来源笔记，右窗格显示目标并获得焦点；来源模式、光标、滚动及缓冲保留，不生成第三个窗格。

若目标已经属于文本模块，按 LINK-02 切换到现有文本标签，不执行笔记窗格重排，不将来源或目标迁移为另一份会话。纯笔记目标继续沿用来源在左、目标在右的规则。

#### Scenario: 笔记来源轮转

- GIVEN 左 A、右 B。
- WHEN 从 A 打开 C，或从 B 打开 C，且被移出笔记保存成功。
- THEN 分别显示 A｜C 或 B｜C，复用需要保留的原会话并释放已移出会话，不常驻第三个笔记编辑器。

#### Scenario: 切换已有文本标签

- GIVEN 左 A、右 B，C 已在文本模块打开。
- WHEN 从 B 打开 C 的有效库内 Markdown 链接。
- THEN 激活文本模块的 C，笔记仍保留 A｜B，返回笔记时恢复原布局。

### Requirement: LINK-05 跳转事务与过期结果

应用必须（MUST）先验证目标边界并查询所属会话。未打开目标先读取，再处理被移出文档的保存，最后一次性提交笔记布局。已属文本模块的目标不再创建笔记读取／会话，按三模块切换协议完成来源笔记保存和文本恢复提交后激活原标签。任何读取／保存／恢复失败或取消均保留原布局及缓冲，异步过期结果不得覆盖较新请求。

#### Scenario: 保存或恢复失败

- GIVEN 笔记有未保存修改，跳转会替换窗格或切换到已打开文本标签。
- WHEN 笔记保存或模块切换的文本恢复提交失败。
- THEN 保留原笔记布局和双方缓冲，提示可重试处理，不提前释放来源或激活半完成状态。

#### Scenario: 快速连续点击

- GIVEN 从同一来源连续请求打开 B 和 C，B 的读取／激活比 C 慢。
- WHEN C 已成功提交，随后 B 的旧结果返回。
- THEN 保持最新 C 的布局／所属模块，废弃 B 的过期结果并释放临时资源。
