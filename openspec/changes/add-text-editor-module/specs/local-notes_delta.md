# Delta: 笔记与文本文件互操作

**Change ID:** `add-text-editor-module`
**Affects:** 新增 FILE-11；沿用 FILE-01～10 和 LINK-01；FILE-07～10 来自待归档整理变更

## ADDED

### Requirement: FILE-11 跨模块文件会话与操作占用

笔记管理必须（MUST）继续仅管理当前根目录内 `.md`，保留原 UTF-8、根目录／链接边界、500 ms 自动保存、相对链接和整理规则。新增文本文件授权不得放宽笔记文件命令的访问范围。

同一规范文件在笔记／文本间最多一份可写会话。通过对话框、笔记树或本地笔记链接再次打开已归属另一模块的文件时，激活所属模块和现有会话，提示文件已打开，不创建独立缓冲；这类跨模块激活不改变原有笔记双窗格布局。

首期笔记文件／文件夹改名、跨目录移动或回收站操作涉及已打开文本文件或其祖先时，必须（MUST）提示先关闭相关文本标签，保留原路径与状态。宿主在文件操作串行区复验占用，防止前端绕过或检查后并发打开。纯排序继续正常执行。切换笔记库不撤销有效的独立文本授权或清空文本状态。

#### Scenario: 同一 Markdown 跨模块打开

- GIVEN 某 `.md` 已在文本模块编辑，或已在笔记窗格打开。
- WHEN 通过另一模块再次打开同一文件，包括大小写路径别名。
- THEN 激活已有所属模块及会话，内容和保存策略不变，不生成第二份可写缓冲；关闭原会话后可改从另一模块打开。

#### Scenario: 文件夹包含活动文本标签

- GIVEN 文本模块打开了笔记库某文件夹下的 `.txt` 或 `.md`。
- WHEN 在笔记树改名、移动或回收该文件夹，或仅调整同级顺序。
- THEN 改名／移动／回收被拒绝并指出相关标签，磁盘和缓冲不变；关闭标签后可重试，纯排序不受影响。

#### Scenario: 换库与后端边界

- GIVEN 文本模块有库外已授权文件和未保存内容。
- WHEN 用户切换笔记库，或尝试用笔记 API 提交该库外路径。
- THEN 文本会话与草稿保留；笔记 API 仍拒绝库外请求，不因文本授权扩大访问范围。
