## Phase 1: 后端文件授权、编码与可靠保存

- [x] 1.1 建立独立文本文件服务及 IPC 数据类型，由 Rust 主持原生多选打开／另存对话框；仅对用户选中的具体文件签发不透明授权 ID，不提供前端任意绝对路径读写接口。
- [x] 1.2 建立规范文件身份与会话占用登记，覆盖大小写、路径别名和可识别的同文件身份；授权读写范围、失效条件、重新授权及关闭释放在后端校验，恢复元数据中的路径不能直接获得写权限。
- [x] 1.3 支持新建与未知扩展名纯文本打开，保留用户选择的扩展名；保持现有笔记 `.md` 过滤、根目录边界、新建／改名限制和 `read_note/save_note` 行为。
- [x] 1.4 实现严格 UTF-8、UTF-8 BOM、带 BOM 的 UTF-16 LE／BE 检测和编解码，拒绝无效字节、无效 Unicode 和不支持的二进制内容；不以替换字符或无 BOM UTF-16 猜测完成打开。
- [x] 1.5 检测并记录 LF、CRLF、CR 及混合换行；正文编辑与原文件编码／换行元数据分离，显式转换可撤销，CR／混合换行在实际保存前确认统一，不静默改写文件。
- [x] 1.6 实现显式保存、另存、全部保存所需后端协议：无修改普通保存不重写，保存请求绑定文件身份、基准磁盘版本及编辑版本；采用同目录临时文件、完整写入和原子提交，提交前再次校验，另存覆盖遵循原生选择及覆盖确认。
- [x] 1.7 处理并发保存、外部替换、只读、删除、锁定、磁盘写入失败、取消与另存冲突；失败保留原文件和内存正文，返回可处理错误，不把旧保存结果当作较新编辑已保存。
- [x] 1.8 在读入前及实际读入时执行单文件 16 MiB 原始字节硬上限，大于 2 MiB 先确认；保存／另存和编码转换后的输出也检查 16 MiB，拒绝超限及读取期间增长，不截断正文后保存。
- [x] 1.9 增加 Rust 字节夹具及故障注入测试：各编码／BOM／换行、混合换行、空文件、中文／空格路径、无效编码、取消、越权 ID、路径别名、覆盖竞态、原文件完整性和无修改保存不写盘。

## Phase 2: 文本会话与本机恢复

- [x] 2.1 新建独立文本会话管理器，将文档标签、可见视图与活动文档分开；最多 12 个文本标签及两个不同文档并排，标签切换复用正文／撤销和编辑设置，不放宽原笔记 `panes` 的两窗格限制。
- [x] 2.2 明确文本显式保存与笔记 500 ms 自动保存策略；分别追踪当前编辑版本、原文件已保存版本、本机恢复已提交版本和保存任务，恢复成功不得清除原文件 dirty。
- [x] 2.3 实现标签排序、切换、关闭／关闭其他及全部保存事务；关闭有修改文档提供保存／放弃／取消，失败或取消保留缓冲；已打开文件复用唯一会话，达到第 13 标签时拒绝且不淘汰现有文档。
- [x] 2.4 对全部文本标签当前正文实施合计 16 Mi 个 UTF-16 代码单元硬上限，覆盖打开、新建、粘贴、替换、撤销／重做和恢复；超限操作整体拒绝并保留原状态。
- [x] 2.5 建立独立版本化恢复目录与清单，存储正文、编辑版本、原文件基准版本、编码／换行、标签／视图和编辑设置；`settings.json` 仅保留设置与必要索引，不承载原始正文。
- [x] 2.6 停止编辑 1 秒后尝试暂存，正常生命周期动作可强制提交最新版本；实现完整代次写入、校验、提交、旧代回收与重启恢复。清单提交前失败保留旧代；提交后清理失败只警告并继续计入配额，不回滚新代确认。
- [x] 2.7 恢复提交由宿主确认已持久化的代次及各文档编辑版本，前端取得匹配凭据后才显示成功；过期提交、重复请求、WebView 更换、提交中继续编辑及宿主校验失败均不能允许丢失最新缓冲的卸载／退出。
- [x] 2.8 恢复目录实施 128 MiB 磁盘硬配额，计入临时文件、当前代和旧代；单代正文合计不超过 64 MiB，单代元数据不超过 128 KiB。写入前预留并在写入过程中限额，不能先越界写入再清理，也不得为腾空间删除唯一有效恢复代次。
- [x] 2.9 恢复时严格校验格式版本、数量、大小、校验值及路径元数据；恢复正文与原文件访问授权分离，外部文件变化／身份不符时保留草稿并要求冲突处理或重新授权，不自动覆盖原文件。
- [x] 2.10 实现旧双模块配置迁移、损坏恢复记录的可见错误与保留策略、关闭／放弃标签后的对应草稿清理；防止旧代次或延迟提交使已关闭文档再次出现。
- [x] 2.11 增加会话及恢复测试，覆盖标签／正文边界、异步竞态、恢复失败、磁盘配额临界值、临时／旧代合计、提交中断、重启、损坏数据及不可信恢复路径。
  - **证据：** 244 项前端及 80 项 Rust 测试，加 7 项原生恢复故障检查；128 MiB 预留拒绝与 128 KiB 元数据拒绝均保持旧清单和确认代次。正文主上限为 16 Mi UTF-16，合法 UTF-8 正文最多 48 MiB；64 MiB 为次级防御边界，本次没有宣称直接写入可接受的 64 MiB 代次。

- [x] 128 MiB 总配额、64 MiB 单代正文、128 KiB 单代元数据及宿主代次确认具有可复现边界测试；恢复状态与原文件保存状态严格区分。
