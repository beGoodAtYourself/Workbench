# Proposal: 新增 Notepad++ 类文本编辑模块

**Change ID:** `add-text-editor-module`
**Created:** 2026-10-16
**Status:** Implemented — Acceptance Pending
**Approved:** 2026-10-16 — 用户调用 openspec-apply

## 问题与目标

拾页目前提供本地 Markdown 笔记及剪贴板。用户希望工程具备类似 Notepad++ 的常用文本／代码编辑能力，并已确认采用「新增独立文本编辑模块」的方向，保留现有笔记管理和剪贴板。

现有 CodeMirror 6 已具备行号、撤销、选区、缩进和本地语言加载基础，但笔记 API 仅管理库内 UTF-8 `.md`，文档会话与两个窗格绑定。用户目前无法在工作台中直接打开普通文本／源码、同时保留多个文件标签、查找替换及控制文件编码和换行。

本提案以日常文本处理、查看日志和编辑代码／配置文件为目标，交付一组有明确边界、可以验收的常用功能。

## 拟议方案

- 顶部增加「文本编辑」，无需选择笔记库即可使用。具有自己的标签、文件命令、编辑区和状态栏，复用当前主窗口及 CodeMirror 6。
- 支持新建未命名文本，以及通过原生对话框选择本地文本／代码文件；最多 12 个标签、两个并排视图，同一文件只保留一个可写会话。
- 支持保存、另存为、全部保存、关闭保护、外部变更检测和冲突处理。文本模块显式保存原文件，笔记模块继续 500 ms 自动保存。
- 支持当前文档普通／正则查找替换、大小写／整词／选区限定、跳转行列、代码着色、可用语言的折叠／括号匹配／注释、缩进、自动换行和多光标编辑。
- 支持 UTF-8、UTF-8 BOM、带 BOM 的 UTF-16 LE／BE，显示并显式转换 LF／CRLF。不以有损解码、静默统一混合换行或截断正文完成保存。
- 自动暂存未命名和未保存内容至本机恢复目录；正常隐藏、切换模块及退出前提交最新恢复版本，唤起／重启恢复标签和草稿。界面区分「已暂存本机」与「已保存到原文件」。

详细行为见 [文本编辑增量规格](specs/text-editor_delta.md)，实现决策见 [design.md](design.md)。

## 范围

### 首期包含

| 能力 | 首期验收边界 |
|---|---|
| 文件与标签 | 新建、原生多选打开、保存／另存／全部保存、关闭／关闭其他、标签排序、键盘切换；最多 12 个标签 |
| 文件类型 | `.txt`、`.log`、`.json`、`.xml`、`.yaml`／`.yml`、`.ini`、常见源码及 `.md`；扩展名不是文本有效性的依据，未知类型按纯文本打开 |
| 编辑 | 行号、可见选区、撤销重做、复制当前行、缩进／反缩进、Tab 或空格与 2／4／8 宽度、换行开关、多光标、跳转行列 |
| 语言 | 复用现有 18 个代码语言入口，另支持 Markdown／XML 和纯文本；按扩展名选择，可手动切换；无对应语言则完整纯文本显示 |
| 搜索 | 当前文档或当前连续选区，普通／正则、大小写、整词、前后查找、单次／全部替换及计数；批量替换一次撤销 |

| 编码与换行 | 有限 Unicode 编码集、严格解码／编码、BOM 检测、显式转换；混合换行保存前确认统一 |
| 会话 | 本机草稿恢复、有界恢复文件、旧配置迁移；切换笔记库不清空文本标签 |
| 发布 | Windows 11 x64，生产构建、独立程序与 NSIS 包、隔离 WebView2 验收及使用说明 |

### 后续考虑

目录／全库／跨标签搜索与批量替换、GBK／GB18030／系统 ANSI 等编码、无 BOM UTF-16 推断、矩形列编辑、宏录制、插件兼容、LSP／调试／代码执行、FTP／云同步、文件对比、打印、文件关联／命令行打开、同文档克隆视图、多窗口、超大日志流式查看不纳入本次交付。

首期单文件原始字节上限 16 MiB，超过 2 MiB 先确认；所有文本标签的当前正文合计上限 16 Mi 个 UTF-16 代码单元。到达上限明确拒绝本次操作并保留原状态。已实现边界及实际验收范围见[验证记录](verification.md)，不以产品限制替代性能实测结果。

## 与现有功能的关系

- 笔记库仍只展示／管理 `.md`，原有根目录边界、Markdown 格式工具栏、双窗格链接规则、排序和移动行为继续适用。
- 文件的规范身份跨模块去重。某文件已在笔记或文本模块打开时，再次打开激活所属模块；不会建立采用不同保存策略的第二份可写缓冲。关闭原会话后可从另一模块打开。
- 首期笔记树对已在文本模块打开的文件或其祖先执行改名、移动、回收站操作时，提示先关闭相关文本标签；纯排序不受影响。后端同样校验，避免旧句柄把内容写回原位置。
- 笔记库切换只重置笔记状态，文本模块与其本机恢复记录继续保留。
- 文本模式不显示 Markdown 排版工具栏，也不执行代码或把文件当作 HTML 页面渲染。

## 架构与兼容考虑

1. 基于 [现有编辑器](../../../src/editor.ts) 和 [语言注册表](../../../src/code-languages.ts) 提取共享编辑基础，保留笔记专用工具栏与链接扩展；不为文本模块引入第二套编辑器引擎。
2. 新文本会话管理器独立于 `Workbench.panes`。最多保留 12 个文本会话及原有两个笔记会话，整个主 WebView 同时最多挂载两个编辑器。只有激活的模块创建视图。
3. 后端主持原生打开／另存对话框，用户选中的具体文件获得不透明授权 ID；不开放任意绝对路径读写，也不把前端提交的恢复路径当成授权。
4. 恢复文件保存正文、编辑版本、基准磁盘版本、编码／换行及视图元数据。恢复保存不清除原文件 dirty；持久化失败阻止会丢失内存缓冲的隐藏／退出／卸载。
5. `Snapshot` 的笔记字段保留；新增文本会话采用独立存储。现有 `set_workspace` 重置会话、`save_snapshot` 两窗格校验和 `main.ts` 模块分支需按模块扩展，不能简单放宽全局数组限制。

工作区已有 `add-folder-reordering-and-moves`、`add-note-reordering-and-moves` 与 `add-launch-at-startup` 的实现和未归档记录。本提案基于这些当前代码，仅在新目录记录需求；不覆盖其文档、验收状态或发布产物。归档时先合并这些变更，再应用本次桌面入口和文件操作增量；自启动 SHELL-05 的「最多两个文档会话」也需按本次资源规格更新。

## 成功标准

- [x] 无笔记库时可新建、打开和保存文本／代码文件；中文与空格路径正确，未经选择的路径不能经 IPC 读写。
- [x] 12 标签与双视图可用，标签切换保留正文／撤销；第 13 个标签和超限正文不触发静默淘汰或截断。
- [x] 查找替换覆盖正则、选区、零宽匹配、无效表达式及超时；替换全程不产生部分修改，一步撤销。
- [x] 编码与 BOM、换行的打开／保存／转换符合字节夹具；无修改普通保存不重写文件，错误输入不被替换字符覆盖。
- [x] 保存并发、外部变化、只读／删除及另存冲突不丢失缓冲，不报告虚假成功。
- [x] 未保存及未命名文本在正常模块切换、隐藏 60 秒卸载、唤起和退出重开后恢复；恢复失败会阻止破坏性生命周期动作。
- [ ] 旧配置迁移、同路径跨模块去重、笔记库切换及文件操作占用规则通过；现有笔记／剪贴板／入口／自启动回归通过。
- [ ] 发布版完整进程内存、唤起和重复操作数据可复现；按资源增量验收，未测量不宣称达标。

## 风险与应对

| 风险 | 概率 | 影响 | 应对 |
|---|---|---|---|
| 多标签与恢复正文增加内存和磁盘占用 | 高 | 中 | 标签／正文／恢复配额，最多两个挂载视图，关闭释放，测量满标签和隐藏状态 |
| 编码／混合换行转换误改原文件 | 中 | 高 | 严格解码、显式转换、原字节版本校验和字节级夹具 |
| 手动保存与后台卸载发生数据丢失 | 中 | 高 | 持久恢复版本凭据、宿主卸载复核、失败保持缓冲及正常关闭三选项 |
| 同文件跨模块或笔记移动造成双写 | 中 | 高 | 规范身份唯一所有者，文件操作占用校验，跨模块和路径别名回归 |
| 正则造成主界面卡死或过期替换 | 中 | 中 | 可终止 Worker、超时／匹配上限、文档版本复验和单事务应用 |
| 恢复损坏或外部文件更换导致误覆盖 | 中 | 高 | 保留恢复副本、读写分权、版本／身份复核、另存或重新授权 |

本机恢复默认在停止编辑 1 秒后尝试提交，正常生命周期动作另行强制提交。强制结束／断电可能丢失最近未提交的输入；恢复记录不代替用户备份。界面应提供清晰的恢复状态和关闭标签时删除对应草稿的行为。
