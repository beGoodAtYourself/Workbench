# Delta: 本地笔记文件管理

**Change ID:** `add-folder-reordering-and-moves`
**Affects:** 同级文件夹排序、跨目录移动、文件树与会话状态

## ADDED

### Requirement: FILE-07 同级文件夹顺序

应用必须（MUST）允许在同一父目录内调整文件夹上下顺序，根目录和嵌套目录均支持。文件夹仍排在笔记之前；排序不得改变磁盘路径、文件名或正文。可通过拖动插入线和“上移／下移”菜单操作，并恢复该父目录默认排序。首尾边界或位置未变化时不产生无效更新。

顺序必须按规范化笔记库根路径隔离，在应用本地偏好中持久保存，兼容没有排序记录的旧安装；不写入笔记目录，不占用现有文档恢复快照。新文件夹追加在已排序项后，多个新增项按名称排序；父目录已有自定义顺序时，应用内重命名保留位置，没有自定义顺序时按新名称排序。移动迁移后代顺序，外部重命名按删除与新增处理。仅成功列出的目录可清理缺失项。偏好失败或超过有界存储上限时必须提示且保留原记录，不截断或伪称保存成功。

#### Scenario: 同级排序与恢复
- GIVEN 同一父目录依次有 A、B、C 文件夹，包含已展开的子目录及笔记。
- WHEN 将 C 拖到 A 之前，或使用“上移”达到该顺序。
- THEN 顺序为 C、A、B，各自子树仍属于原父目录；刷新、折叠展开、隐藏卸载和重启后顺序保持，切换其他笔记库不串用偏好。
- AND 恢复同级默认排序后只移除该层自定义顺序，后代设置及笔记路径不变。

#### Scenario: 目录变化与偏好异常
- GIVEN 已保存自定义顺序，随后新建、重命名或删除文件夹，或外部程序改变目录。
- WHEN 应用操作成功或刷新成功读取对应目录。
- THEN 有效既有项保持相对顺序，新增项按规则追加，应用内改名保持原位置；读取失败不清空顺序。
- AND 纯排序保存失败时还原此次排序并提示；损坏或超限记录不被空配置覆盖。

### Requirement: FILE-08 文件夹层级移动

应用必须（MUST）支持将单个真实文件夹移入同一笔记库的其他文件夹或根目录，以及在另一父目录的同级文件夹之前／之后插入。移动完整目录及所有内容，保持名称和文件字节，不合并或覆盖已有目标。根目录不能被移动；不能移入自身或后代；源和目标必须满足 FILE-06 的后端路径边界。跨父目录移动必须在确认前展示源／目标路径，并说明 Markdown 相对链接及图片引用不会自动更新。

拖动必须以插入线表示前后位置、以目标高亮表示移入，通过中文提示说明动作。无效落点不得操作文件；Esc、失焦、指针取消或取消确认不改目录和顺序。须提供可用键盘操作的“移动到…”目标弹窗。长列表支持边缘滚动与正确的虚拟行命中，拖动结束后释放监听、滚动与过期工作。

#### Scenario: 移入目录或移回根目录
- GIVEN `项目/资料` 包含笔记、图片及其他文件，根目录另有 `归档`。
- WHEN 将 `资料` 拖到 `归档` 中部并确认，随后拖到笔记库名称并确认。
- THEN 路径先变为 `归档/资料`，再变为根目录的 `资料`，内容与名称完整保留，移动结果在目标文件夹组末尾可定位。

#### Scenario: 跨父目录指定位置
- GIVEN `项目/资料` 与根目录的 `归档` 不属于同一父目录。
- WHEN 将 `资料` 拖到 `归档` 行上沿的插入线并确认。
- THEN `资料` 移至根目录并排在 `归档` 前，不误变成 `归档` 的子目录。
- AND 提交前复验插入锚点仍为目标父目录的有效直接子文件夹；若锚点消失或迁移则在磁盘移动前拒绝，不静默改为追加。纯排序也必须复验锚点。

#### Scenario: 无效目标、取消或文件系统失败
- GIVEN 目标同名、属于源的后代、超出根目录边界，或源／目标在确认期间失效或变得不可写。
- WHEN 用户提交移动，或外部程序在提交时创建同名目标。
- THEN 后端重新校验并拒绝无效操作，不覆盖、不合并、不退化为复制后删除，保留原文件及缓冲并说明原因。
- AND 用户取消、Esc 或无效区域释放不启动磁盘移动；同父目录无位置变化时不操作文件。

### Requirement: FILE-09 移动事务与会话一致性

目录移动必须（MUST）遵循现有保存与冲突协议，在路径改变前处理打开文档的未保存内容，串行执行相冲突的文件操作。成功后同步受影响文档和后代路径、选中项、展开项、目录缓存、排序及恢复记录，保留模式、光标、滚动和正文撤销。旧读取、导航、预览、刷新或工作区请求不得恢复旧路径、改写新页面或操作另一个笔记库。

磁盘移动失败时不得提前确认新路径；磁盘成功后排序或恢复记录保存失败时，必须保留新路径并准确报告部分成功，可重试偏好保存，不能假装目录仍在原处或自动反向移动。意外退出后缺失旧路径不得通过自动保存重新创建。

#### Scenario: 双窗格含未保存内容
- GIVEN 两个窗格打开移动目录内的笔记，其中一篇正在自动保存或存在未保存修改。
- WHEN 用户确认移动该目录。
- THEN 等待保存处理成功才移动，保存失败则保留原路径和缓冲；移动成功后两个原会话继续工作，下一次编辑与保存使用新路径，预览以新目录解析相对地址。

#### Scenario: 旧请求与部分成功
- GIVEN 移动前已发起慢速导航／刷新，或磁盘移动成功后排序／恢复记录写入失败。
- WHEN 旧结果返回或元数据失败上报。
- THEN 旧结果不能恢复旧路径；已移动的文档仍指向新路径，界面分别报告移动成功与元数据未保存，并允许重试后者。
- AND 意外退出重启后按真实磁盘显示目录，旧恢复路径缺失只提示，不重新创建文件。
