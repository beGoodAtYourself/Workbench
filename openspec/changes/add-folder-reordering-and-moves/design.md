# Design: 文件夹排序与移动

**Change ID:** `add-folder-reordering-and-moves`
**Status:** Implemented
**Completed:** 2026-09-14

## 既有基础与本次调整

- `files.rs` 的 `list` 继续返回文件夹优先、名称排序的基础结果；展示层合并自定义顺序，`rename` 仍处理同父目录更名，跨目录操作通过新增接口执行。
- `main.ts` 文件树保留固定行高虚拟列表，文件夹拖动允许随自动滚动重绘，并按当前路径重新命中目标，不保留过期 `data-row`。
- `freeze` 串行化文件操作并使旧树请求失效；新增 `Workbench.beginFileOperation` 使在途导航和刷新结果失效，等待保存完成后才允许目录操作。`Workbench.remap` 保留文档对象并修改路径。
- 会话快照最多含两个窗格、300 个展开项，序列化上限 32 KiB，切换根目录清空会话。排序必须独立持久化。

## 拖动与落点

拖动状态保存来源根目录标识、来源路径、指针 ID 与操作意图。文件夹行上／下各四分之一区域表示插入，其余中部表示移入；边界以可见提示为准。整棵展开子树随父文件夹排列，不可插入到别人的子树内部而仍假装同级。

当来源与目标父目录相同，边缘落点是排序；不同则是移动加定位。笔记行与文件树空白区不给文件夹落点，根目录通过笔记库名称明确命中。文件夹拖进正文仍提示不支持插入链接；笔记拖进编辑器保留原有插入链接流程，笔记拖到文件树不触发移动。

靠近文件树上下边缘时按帧滚动，并持续重算虚拟行和落点；拖动结束、Esc、窗口失焦、pointercancel、来源失效、隐藏或工作区切换时停止滚动并释放 pointer capture。异步展开目标或刷新返回后必须检查工作区与拖动代次。悬停可按需展开有效目标，不突破原有 300 个展开目录限制。

菜单提供可聚焦的“上移”“下移”“移动到…”和“恢复同级默认排序”。目标弹窗只列当前层级目录，支持进入、返回上级及根目录，拒绝自身及后代；确认前显示最终路径。所有控件有中文可访问名称，拖动结束不额外触发点击开关目录。

## 排序记录

使用版本化的独立偏好记录，路径为应用配置目录下 `tree-order/<规范化根路径的摘要>.json`。文件内包含版本、根目录标识、以父目录相对路径为键的文件夹次序；次序项只存直接子文件夹相对路径。摘要由后端生成，不采用来自前端的任意文件名。

只加载当前笔记库的排序映射；其他库的偏好保留在磁盘，切库后释放旧映射。将已有排序与 `list` 的真实目录项合并：保留有效已排序项，其余按名称追加，笔记沿用基线顺序。旧安装缺少排序记录时使用默认顺序，无正文或会话迁移。应用内重命名／移动映射父键与后代路径；回收站成功后删除受影响记录。

读取失败或内容不合法时提示并使用可用默认顺序，不把错误写成空配置覆盖原文件。每库排序记录上限 1 MiB，在读取及保存前检查；超过上限保留已有记录并说明本次自定义顺序无法保存，不截断。单元测试覆盖超限与损坏记录。

排序更新走串行保存，以临时文件替换方式提交；检查预期工作区和记录版本，避免旧快照覆盖新顺序。纯排序仅在持久化成功后确定最终 UI 状态，失败还原原次序。“恢复同级默认排序”仅移除该父目录的自定义次序，不清除后代设置。

## 文件夹移动事务

仓库新增 `folderOrder()`、`arrangeFolder(action)` 和 `retryFolderOrder(root)`，分别桥接 `folder_order`、`arrange_folder` 和 `retry_folder_order`。`FolderAction` 包含预期工作区 `root`、记录版本 `revision`、来源相对路径 `source`、目标父目录 `parent`、可选锚点 `anchor` 及落点 `placement`（`before`／`after`／`inside`／`reset`）。响应包含最终路径、是否发生磁盘移动、最新排序记录及可选警告。排序与移动使用同样的工作区及版本校验。

1. 确定意图并显示跨父目录确认。确认后进入文件操作互斥区，冻结输入，禁止并发切库／更名／回收站／隐藏卸载；清理待写旧会话快照，使旧导航及树刷新结果失效，并等待正在进行的保存完成。旧读取无需等待，其迟到结果与错误均由代次检查丢弃；会话快照写入串行执行。
2. 沿用现有保存协议处理打开文档的 dirty／冲突；保存失败则终止移动并保留缓冲，不以移动绕过冲突。前端操作互斥覆盖此过程，后端移动命令在保存完成后才进入 I/O 锁，避免持锁等待仍需该锁的保存请求。
3. 后端在同一 I/O 串行区重新检查工作区标识、源为真实目录、目标为有效父目录、规范路径边界、同名及自身／后代关系。指定插入锚点时，还须确认它仍存在、是真实文件夹且仍为目标父目录的直接子项；否则在磁盘移动前拒绝并要求重新选择，不静默改为追加。纯排序提交同样复验来源、父目录及锚点。复用现有 Windows 大小写、路径分段、链接／junction 边界规则，不能仅依赖 UI 的字符串判断。
4. Windows 使用 `MoveFileExW` 且 flags 为 0 移动整个目录，提交时不替换已有目标。目标不存在的预检查不足以代替提交时的不覆盖保证；竞态中新建同名目标也必须失败。不通过递归复制后删除回退，不遍历正文；不能直接移动时明确失败。
5. 磁盘成功后一次性映射打开文档、选中项、展开项、排序父键及后代路径；清理目录缓存和旧预览任务，刷新源／目标父目录，保留文档对象、模式、光标、滚动及撤销。折叠目标按需展开至能显示移动结果，仍遵守展开上限；达到上限时定位目标父目录并明确提示。
6. 持久化排序与会话。磁盘操作与偏好文件不假定为一个原子事务：若后续持久化失败，响应区分“已移动”与“顺序／恢复记录未保存”，前端继续使用新路径并允许重试偏好保存。不得为回滚 UI 再移动文件。

若进程在目录移动之后、恢复记录保存之前退出，下次启动按磁盘现状列树；缺失旧路径按既有规则提示，不重新创建旧文件，不自动推断重定位。该限制在失败验收中明确记录。

应用内重命名或回收站成功后，若排序记录迁移／清理失败，也适用磁盘结果优先的部分成功处理：提示偏好未保存并保留实际文件状态，不以纯排序回滚规则恢复已更名或已回收项目。

## 引用与资源

与重命名一致，不自动改写 Markdown。目录内部文件间的相对位置保持时引用可继续使用；跨目录链接、外部指向移动目录的链接以及部分图片引用可能失效，移动确认和说明必须覆盖。移动后的预览重新以新笔记父目录解析相对地址。

排序或目标浏览仅读取目录元数据，不递归扫描全库正文；复用虚拟列表和既有两文档上限。拖动、弹窗和过期任务卸载时清理监听与帧回调，不扩展历史性能验收结论。
