# 文本编辑多编码支持（2026-10-29）

原先独立文本编辑只接受 UTF-8 和带 BOM 的 UTF-16，导致 GBK、Big5 等普通文本无法打开。本次扩展到 47 个明确的读写编码选项，并提供手动指定读取编码的入口。

## 使用方式

- 「打开文本文件」自动识别；按 BOM、无 BOM UTF-16／UTF-32 特征、严格 UTF-8、旧式编码检测的顺序解码。ISO-2022-JP 转义序列单独识别。
- 「更多 → 指定编码打开」用于无法自动打开或已知编码的文件。
- 「更多 → 以其他编码重新打开」重新解释原始字节；有未保存修改时，按钮明确提示丢弃修改，取消保留当前正文。
- 状态栏「文本编码」选择保存时的编码，支持撤销／重做。其作用是转换输出；修复乱码应使用重新打开。
- 手动读取编码及保存后编码记录在宿主原有文件授权中，恢复草稿、磁盘探测及再次保存继续使用该设置。旧恢复记录可继续读取。
- 保存转换同时校验编码失败和反向解码一致性；无法表示的字符不会被替换成问号或 HTML 数字实体，原文件保持不变，可改选 UTF-8 等编码保存。

## 编码范围

| 系列 | 支持选项 |
| --- | --- |
| Unicode（10） | UTF-8 有／无 BOM；UTF-16、UTF-32 各自 LE／BE、有／无 BOM |
| 中文（3） | GBK（兼容 GB2312／CP936）、GB18030、Big5（CP950） |
| 日韩（4） | Shift_JIS（CP932）、EUC-JP、ISO-2022-JP、EUC-KR（CP949） |
| Windows（10） | Windows-1250～1258、Windows-874（兼容 TIS-620） |
| ISO（14） | ISO-8859-1、2、3、4、5、6、7、8、8-I、10、13、14、15、16 |
| 其他（6） | ASCII、KOI8-R／U、IBM866、Macintosh Roman／Cyrillic |

选项数包含同一 Unicode 编码的 BOM／字节顺序变体，别名不另计。传统编码映射采用 [encoding_rs](https://docs.rs/encoding_rs/0.8.42/encoding_rs/)，自动检测采用 [chardetng](https://docs.rs/chardetng/0.1.17/chardetng/struct.EncodingDetector.html)；ASCII、ISO-8859-1 和 UTF-32 单独严格实现，避免网页标签别名把 Latin-1 或 ASCII 当作 Windows-1252。

自动识别属于推测：短文本、无明显零字节特征的无 BOM Unicode、混合编码文件不保证正确，应手动选择；不声称支持全部历史编码。混合换行、16 MiB 文件限制、二进制拒绝和原文件冲突保护继续生效。

## 验证

- 248 项前端单元测试通过，覆盖扩展编码草稿校验、编码重读参数、失败及过期响应保留输入。
- 87 项 Rust 测试通过，覆盖全部 47 个选项往返、Unicode BOM／字节序、固定 GBK／Big5／日韩／西文字节样本、自动识别、非法序列、无损转换保护、授权与编码持久化、仅编码变化但字节不变、外部变更与原文件保留。

- Windows x64 发布版与 NSIS 安装包构建成功，独立保存到 `src-tauri/target/text-encodings/release/`；[交付哈希与源码校验](raw/text-encodings-delivery.json)。
