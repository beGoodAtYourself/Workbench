## 实测中修复的问题

- 原生 WebView 的 HTML5 拖拽不稳定，改为工作台内部 Pointer Events 拖拽，落点交给编辑器坐标映射。
- 编辑器重挂载时重新绑定当前文档回调，同时保留撤销状态，避免回调继续引用已销毁的视图。
- 较慢的右窗格关闭保存不能覆盖较新的导航结果；过期刷新结果不能覆盖随后已经保存的新编辑。
- 保存、切换目录、重命名和保存副本期间冻结相关界面，避免保存后又产生未处理的新输入。
- 大量中文及表情剪贴板一次排版会卡顿，改成有字符边界保护的分段浏览；单次保留仍上限 1 MiB。
- 悬浮入口改用原生 Win32 窗口，隐藏卸载计时使用单个 Condvar 工作线程。

## 大内容成本

这些是顺序执行边界场景时的五次样本 P95，包含宿主及全部 WebView2 子进程，不属于普通 100 KiB 笔记的三轮预算验收。切换到较小内容后，运行时可能仍保留此前分配的内存，表中不能理解为每个对象的独立增量。

| 场景 | 私有工作集 P95 |
| --- | ---: |
| 大于 1 MiB 的中文/表情剪贴板，分段显示 | 211.39 MiB |
| 大于 2 MiB 的长行笔记，确认加载后切换编辑 | 459.29 MiB |
| 恰好 2 MiB 的多行笔记，编辑器 DOM 有界 | 433.90 MiB |
| 随后切换到含本地图片的短笔记 | 295.63 MiB |

原始 PID、Private Bytes 和私有工作集记录分别见 `raw/large-clipboard.json`、`raw/over-two-mib-long-line.json`、`raw/two-mib-editor.json`、`raw/local-image.json`。两种大笔记均完整读取；取消大文件提示时布局保持不变，长行和多行未被截断后保存。本地图片正常显示，远程图片保留占位。

## 后续复测方法

在 Windows 11 x64 上构建发布版，退出其他拾页实例，再执行：

```powershell
python scripts/make-fixtures.py
node scripts/native-benchmark.mjs edges
node scripts/native-benchmark.mjs memory
node scripts/native-benchmark.mjs stress
node scripts/native-benchmark.mjs wake
```

当前内存脚本使用 PDH 性能计数器，需要当前账户具有读取权限；旧 WMI 脚本仅保留作历史参考。测试脚本只启动 `.qa/benchmark-*/shiye.exe` 并使用 `.qa/notes`，运行结束关闭自己的进程。边界脚本会把系统剪贴板设置为生成的验收文本、空内容或测试格式；不会读取或记录此前个人剪贴板内容。复测期间不要在这个隔离实例中编辑个人笔记。

基准生成 50 个目录，每个目录 20 篇恰好 20 KiB 的笔记；另外包含 A/B/C 三篇恰好 100 KiB 的测量样本以及边界夹具。正文不整库预读。

内存按宿主 PID 递归收集所有后代，每个 PID 仅计一次；同时记录私有工作集与 Private Bytes。计划的完整流程为普通状态预热 10 秒，每组 30 次采样，三轮；隐藏时等待 65 秒确保释放。本次只执行了上表记录的部分。循环测量在同一 WebView 内执行，先预热十轮，再测量 100 轮，前后各等待 60 秒稳定。

性能脚本显式启用本地 CDP 和 `SHIYE_PROFILE=1`，日常运行没有 CDP 端口。唤起埋点以进入应用显示处理函数为起点，以文档视图建立后首帧为终点；原始时间包括文件读取及界面重建，不包括测试进程派发之前的时间。冷唤起重复测试用已隐藏窗口的 `profile_unload` 快进 60 秒计时；真正的 60 秒释放由内存场景独立验证。此测量和人工按键到可交互的端到端时间有边界差别，应单独说明而不混用。
